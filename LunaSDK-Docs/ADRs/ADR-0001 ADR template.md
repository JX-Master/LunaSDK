> This is a template for drafting new ADRs (architecture decision record) in LunaSDK. **An Architecture Decision Record (ADR) is a document that captures a significant architectural decision, its context, rationale, and consequences to support knowledge sharing and decision tracking.** 
> Texts in quote format like this are hints on how to write each part of ADR and should be removed in formal ADRs.

> ADRs are numbered using ADR-XXXX format, starting from 0001.
## Status
Approved.
> The status has the following options：
> 1. Proposed: This decision is proposed, but has not been taken effect yet. Further review and discussion is required to approve the decision.
> 2. Approved: This decision is approved and is effective.
> 3. Rejected: This decision is rejected and will not take effect.
> 4. Retired: This decision is overturned/superseded by a new decision and is no longer effective. New ADR that overturns this ADR should be citied.
